---

# Purpose

The Enterprise Architecture Lifecycle defines the states through which every Enterprise Architecture document progresses.

---

# Lifecycle States

## Draft

Initial document under development.

---

## Review

Technical review for consistency and completeness.

---

## Approved

Accepted for use by the Founder.

---

## Active

Current authoritative version.

---

## Superseded

Replaced by a newer approved version.

---

## Archived

Retained for historical reference only.

---

# Transition Rules

Draft → Review

Review → Approved

Approved → Active

Active → Superseded

Superseded → Archived

No lifecycle state may be skipped.

---

# Version Management

Major Version

Architecture changes.

Minor Version

Feature additions or improvements.

Patch Version

Documentation corrections.

---

# Approval Criteria

Before becoming Active:

- Constitution compliant
- Framework compliant
- ADR references verified
- Security reviewed
- Dependencies documented

---

# Guiding Principle

Enterprise Architecture evolves through controlled governance rather than uncontrolled modification.
